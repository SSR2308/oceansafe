A mobile-first web app that combines live ocean/beach conditions, an AI safety chatbot, and community hazard reporting into one platform. Built solo as a working Streamlit prototype to validate the concept before a native app — the write-up below is honest about what's actually built versus what's still the pitch.

Overview

🔗 View code on GitHub

The pitch: combine real-time ocean data, AI insights, fishing guidance, and community reporting into one platform to keep beachgoers — surfers, swimmers, lifeguards, and families — safe and informed at Southern California beaches. It placed in the Top 10 for California's 47th Congressional District in the Congressional App Challenge.

Rather than build toward a native app blind, I built a working Python/Streamlit prototype first — real APIs, a real chatbot, a real map — to validate the concept, the data integrations, and the chatbot before committing to the bigger iOS/Firebase build the original pitch scoped.

What's actually built

Three working pieces, all live in the Streamlit prototype:

  • Beach Safety Dashboard — live weather (OpenWeatherMap) and NOAA tide predictions for six Southern California beaches (Santa Monica Pier, Venice Beach, Malibu Surfrider, Huntington Beach, Newport Beach, Laguna Beach), each with visitor info like parking, hours, and dog policy.
  • Interactive hazard map — a Mapbox GL map centered on the user's live location; click anywhere to drop a geotagged hazard report (jellyfish, trash, high surf, broken glass, etc.), with turn-by-turn walking directions to the selected beach.
  • Tidebot — a retrieval-augmented AI chatbot that answers beach-safety questions grounded in a curated knowledge base, rather than making things up.

Tidebot's RAG pipeline

Tidebot embeds each incoming question with OpenAI's text-embedding-ada-002, retrieves the top-matching chunks from a Pinecone vector index built from a curated beach-safety knowledge base, and passes those chunks as context to gpt-4o-mini through a LangChain prompt template. The prompt explicitly instructs the model to answer only from the retrieved context and to say so if the answer isn't in it, rather than filling gaps with general chatbot knowledge — the jellyfish-sting answer in the screenshot above, for example, is grounded in a specific first-aid source rather than generic web knowledge.

Vision vs. what's built

The original pitch scoped a fuller MVP — real-time NOAA/Surfline/local-government hazard alerts with push notifications, first-aid guidance baked into the AI assistant, a fishing guide with CA regulations and catch limits, and a color-coded green/yellow/red safety rating per beach. The prototype validates the core concept (live data, AI chatbot, hazard reporting) but doesn't yet cover push alerts, the fishing guide, or the color-coded rating system. Stretch goals beyond that include gamified hazard reporting, an AR rip-current overlay, AI hazard detection from photos, and multilingual support (Spanish, Vietnamese, Korean).

Tech stack: Python · Streamlit · LangChain + OpenAI (gpt-4o-mini) · Pinecone · NOAA Tides & Currents API · OpenWeatherMap API · Mapbox GL JS
